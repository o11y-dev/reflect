Explore the evidence gap

Your work stays on your machine.

Reflect reads local agent telemetry and supported native session stores into a local SQLite database. The dashboard, CLI, and MCP tools work from that evidence.

  • Text capture is a choice. Prompt and response capture is opt-in; metadata capture is the setup default.
  • You review changes. Workflow discovery does not silently install a skill. Approval and installation are explicit actions.
  • Unknown stays unknown. A completed command, an agent's report, and a verified result are different kinds of evidence.

Review the install scriptOther installation options

On a new installation, the script installs Reflect and runs reflect setup. Setup configures local telemetry, hooks, and selected agent integrations. Interactive setup lets you choose integrations and text-capture settings; non-interactive setup uses available agents with metadata capture.

Package managers and existing installs

The installer prefers pipx, then uv, then an isolated pip environment. For an existing installation it updates the package while preserving setup. Review the script above before running it.

  1. Choose one agent during setup.

    Use an agent listed as supported below. Optional prompt and response capture remains your choice.

  2. Check capture with reflect doctor.

    Review the integration status. Configured integrations still need a task to produce evidence.

  3. Run a normal coding task.

A closer look, when you need it.

Inspect usage, share reviewed routines, and connect existing tools. Start with the evidence from your own work.

Where did the tokens and cost go?

Explore observed input, output, and cache usage alongside tools and task activity. Cost depends on available model and pricing evidence. Missing usage is not treated as zero, and provider invoices remain a separate source.

Can this support team capacity decisions?

Use scoped usage and workflow evidence to explain demand and proposed improvements. A high token count alone does not establish waste, and a change in outcomes does not automatically establish that a skill caused it.

How do skills and memory fit together?

Reflect keeps telemetry evidence and reviewable skills in its local store. Optional memory integrations can supply additional context. External recall remains distinct from verified session evidence. Read about memory integrations.

What does the public example contain?

The report uses a fictional, deterministic dataset processed through Reflect. Its sessions, skills, and outcomes are illustrative. It contains no exported private sessions. The local dashboard shows your own captured evidence.

What does this website measure?

The public website records example interactions, GitHub clicks, and successful install-command copies through its existing analytics integration. A click does not establish a star, and a copied command does not establish an installation. Local dashboard navigation is excluded.
